# OIDA 2.0 Product Vision

## Product definition

OIDA 2.0 is an AI-first project delivery operating system with human-controlled
authority. It actively turns project context into reviewable requirements,
solution direction, an executable plan, validation evidence, and an acceptance
package. It continuously identifies the next useful action and asks for human
attention only when judgment, correction, exception handling, or authority is
needed.

## User and problem

The primary user is a delivery lead accountable for moving a project from intent
to accepted outcome. Contributors, architects, QA leads, sponsors, and approvers
participate through the same project workspace. Today they reconstruct project
truth across documents, task tools, test systems, and conversations, then spend
large amounts of time drafting, reconciling, chasing gaps, and reporting.

## Product promise

Given sufficient grounded context, OIDA produces the first useful pass of project
artifacts, maintains inspectable traceability, detects delivery gaps, and prepares
decisions and acceptance. People can inspect sources, edit, compare, reject,
regenerate, override, commit, or approve according to explicit authority.

## Design outcomes

- One project workspace and coherent delivery flow, not a menu of subsystems.
- One grounded view of what is approved, active, blocked, validated, and pending.
- AI output is a candidate until a person or permitted policy commits it.
- Low-risk reversible work is automated; high-authority decisions remain human.
- Failure, uncertainty, missing configuration, and stale context are explicit.

## Success hypothesis

The MVP succeeds when one real project can complete Context → Definition → Plan →
Delivery → Validation → Acceptance with materially less manual preparation, no
loss of human control, and no invented project truth.

## Non-goals for the MVP

Portfolio management, commercial/contract management, production deployment,
generic workflow building, autonomous multi-agent teams, predictive analytics,
and replacement of specialist PM/QA/document systems are excluded.
