# OIDA 2.0 Phase 1 Recommendation

Proceed to a **thin vertical product slice**, not platform construction. Phase 0.1
resolved historical recovery and owner-write policy and supplied defaults for the
project archetype, roles, source formats, and logical ownership. During inception,
close provider constraints and measurable value targets; tune AI finding thresholds
during the pilot.

## Recommended sequence

1. Select one representative software-delivery brief and measurable manual
   baseline. Define authority roles and acceptance criteria.
2. Prototype the workspace journey and three gates with realistic artifacts;
   usability-test whether users can answer “what needs attention next?”
3. Run technical spikes for grounded source extraction, structured requirement and
   delivery candidate generation, context manifests, and output validation.
4. Define modular architecture from the ownership table, favoring one deployable
   product slice with ports for identity/document/PM/QA/Conductor boundaries.
5. Implement the smallest walking skeleton from source → candidate → commit → truth
   projection → acceptance package, including audit and failure paths from day one.
6. Add execution/validation materialization and the five MVP gap detectors, then
   pilot against the selected project and measure correction, grounding, authority
   violations, time saved, and completion.

## Phase 1 guardrails

No generic capability registry, vector/graph platform, multi-agent framework,
portfolio layer, comprehensive connector suite, or service decomposition without
evidence from the vertical slice. AI output quality and failure behavior are tested
with fixed evaluation cases before automation is raised above L2.

## Phase 1 exit

The proof scenario completes end to end; authority tests show no prohibited action;
sources and committed outputs are traceable; outage/manual paths work; and measured
results justify continuing to production-grade MVP hardening.
