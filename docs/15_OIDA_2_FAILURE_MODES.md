# OIDA 2.0 Failure Modes and Controls

| Failure | Prevention / detection | Recovery |
|---|---|---|
| Capability explosion | Every capability maps to MVP requirement and Golden Flow gate. | Remove or move to P1/Later. |
| Menu-driven design | Workspace starts with truth, next action, blockers, and decisions. | UX review against real scenario. |
| Registry-first architecture | Fixed MVP action policy and typed links. | Add extensibility only from proven need. |
| Integration theater | End-to-end outcome, ownership, freshness, conflict, and failure tests. | Mark degraded/blocked; never claim workflow success. |
| Fake completeness | Acceptance gates validate coverage/evidence/business authority. | Return for rework with gaps. |
| AI advisory trap | AI produces candidates and policy-bounded actions, not only chat. | Track time saved and materialized outputs. |
| AI autonomy trap | Deterministic max levels and human-only high authority. | Block, audit, escalate. |
| Approval fatigue | Three material human gates; L3/L4 routine actions reviewed by exception. | Tune risk/attention policy. |
| Shared truth | Explicit owner per concept and reference-based projection. | Show conflict/freshness; reconcile at owner. |
| Generic CRUD | Domain commands, baselines, gates, and typed evidence semantics. | Reject UI/API designs that bypass lifecycle. |
| Hallucinated truth | Source manifests, structured validation, provenance, confidence. | `GROUNDING_INSUFFICIENT`; human/manual path. |
| Stale context | version/freshness metadata and invalidation. | Regenerate candidate; never mutate baseline silently. |
| Irreversible automation | reversibility and compensation required by policy. | Escalate irreversible actions to L0/L1. |
| Notification spam | deduplication, severity, ownership, actionable findings. | Suppress routine success; tune thresholds. |
| Baseline drift | immutable active versions and traceability checks. | create revision and mark downstream review. |
| AI/provider outage | explicit runtime states and manual workflow. | retry/change configuration or continue manually. |
| Sensitive context leakage | access-aware assembly and minimal context manifest. | block run, audit, revoke output access. |
