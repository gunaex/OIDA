# Phase 2 Known Gaps

- One canonical live DeepSeek project has passed; broader project diversity and
  repeated quality/correction-rate measurement remain future pilot work.
- The browser uses a validated structured JSON editor for deep solution/plan edits;
  richer field-specific forms and visual dependency editing are future UX work.
- Browser automation and visual-regression testing are not included; API Golden
  Flow and JavaScript/runtime smoke provide current evidence.
- SQLite remains a local deployment choice; production concurrency, backup and
  operations require a later persistence decision.
- Effort classes and timeline assumptions need team calibration; no schedule or
  delivery promise is inferred.
- Multiple committed solution/plan histories are supported, while advanced branch
  comparison/change-impact workflow is deferred.
- Required validation scope, execution materialization, PM/QA/Infra owner sync,
  evidence and Gate 3 remain deliberately outside Phase 2.
- DeepSeek high-reasoning solution and plan calls took roughly three to four
  minutes; a future durable background-job UX should replace synchronous waiting.
- Quantitative correction-rate and time-saved targets need a real-project pilot.

These gaps do not weaken human authority, project isolation, exact provenance,
staleness blocking, deterministic dependency checks or baseline immutability.
